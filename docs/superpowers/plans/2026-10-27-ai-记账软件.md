# AI 记账软件 实现计划

> **Goal:** 构建一个「为 AI 记账而生」的本地记账工具：Node.js 后端 + SQLite + 原生 HTML 前端 + 鉴权 API + skill 文档 + 邮件备份。

**Architecture:** 单进程 Node.js 服务（Express），SQLite 单文件存储，`/api/*` REST 接口供 AI 调用，`/` 提供 Web 界面。核心域逻辑（账户平账、现金归零、周期账）抽成纯函数模块，用 node:test 做 TDD。

**Tech Stack:** Node.js 22+、Express、better-sqlite3、node:test（内置测试）、原生 HTML/CSS/JS 前端、nodemailer（邮件备份）。

**Spec:** `docs/superpowers/specs/2026-10-27-ai-记账软件-design.md`

## Global Constraints

- 所有 `/api/*`（除 `/api/login`）需 `Authorization: Bearer <token>`。
- 网页访问需密码（登录后设 session cookie）。
- 存储：SQLite 单文件 `data/zhangben.db`。
- 金额统一用「分」（整数）存储，展示时 `/100` 格式化为两位小数，避免浮点误差。
- 现金账户是平账中转枢纽，差额方向必须正确。

## Task 分解

### Task 1: 项目脚手架 + 数据库层
- 初始化 package.json、装依赖（express、better-sqlite3、nodemailer、cors 可选）。
- `src/db.js`：建表（accounts / entries / receivable_payable_items / periodic_entries / categories / settings）+ 种子数据（默认分类 + 示例账户 + 现金账户）。
- 测试：数据库能初始化、种子分类存在、现金账户存在。

### Task 2: 域逻辑 —— 账户 + 平账（TDD 重点）
- `src/domain/accounts.js`：账户 CRUD、`flatten(实际余额映射)` 平账逻辑。
- 平账规则：给定各账户实际余额，`差额 = 实际 - 账面`，每笔差额生成一条「转账」流水（差额为正→从该账户转入现金；差额为负→从现金转出到该账户），并更新账户余额。
- 测试覆盖：正差额、负差额、现金账户自身不动、余额最终对齐实际值。

### Task 3: 域逻辑 —— 记账 + 现金归零（TDD 重点）
- `src/domain/entries.js`：记账（收入/支出/转账）、单条修改/删除、`balance()` 记平账记录清零现金。
- 记账规则：支出→现金减少；收入→现金增加；所有明细从现金走。
- `balance()`：计算当前现金余额，生成一条 `is_balance` 记录使现金归零（方向 = -现金余额）。
- 测试覆盖：支出/收入对现金的影响、平账记录金额 = -现金余额、执行后现金归零。

### Task 4: 域逻辑 —— 周期账 + 报告
- `src/domain/periodic.js`：周期账 CRUD、`runDue(now)` 检查到期并生成流水。
- `src/domain/report.js`：总资产（资产-负债）、净资产、本月汇总。
- 测试覆盖：到期的周期账生成流水并更新 next_run、未到期不生成、总资产计算正确。

### Task 5: 鉴权 + API 路由
- `src/auth.js`：登录签发 token（简单共享密钥 + 登录接口）、鉴权中间件。
- 各 routes 文件接域逻辑。
- 测试：无 token 401、错误 token 401、正确 token 通过。

### Task 6: 前端界面
- `public/` 三件套：资产页、负债页、应收应付页、账单流水页、录入页、周期账管理页、设置页。
- 风格对齐口袋记账：浅米白背景、蓝色主色、多彩账户卡片、数字键盘。
- 通过 node:test 或手工 curl 验证 API 与页面连通。

### Task 7: skill 文档 + README + 邮件备份
- `SKILL.md`：写给后续 AI 的记账操作手册（登录、平账、记账、周期账、查报告）。
- `README.md`：启动、默认密码、SMTP 配置、备份方式。
- `src/backup.js`：SMTP 定时备份 .db 文件，未配 SMTP 则跳过。
