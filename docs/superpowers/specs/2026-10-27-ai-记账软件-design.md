# AI 记账软件 设计文档

> 2026-10-27 · 作者：kevinxia 需求 + WorkBuddy 设计

## 1. 意图（Intent & Why）

用户现在用「口袋记账」记账，但每月手动录入太麻烦。核心诉求不是重做一个记账 App，而是：

- **保留**口袋记账已经完备的账户模型和分类体系；
- **改造录入方式**：从手动一笔笔输入，改成「发截图给 AI → AI 调 API 自动平账 + 记账」；
- **改造展示方式**：按自己想要的定制方式展示。

本质是一个「**为 AI 记账而生的、带 Web 界面的记账后端**」。

## 2. 核心记账模型（这是灵魂，必须精确）

用户**一个月只记一次总账**，不关心日常流水细节。流程：

1. **平账**：把每个账户（余额账户 + 负债账户）对齐到实际金额。对齐不是简单加减，而是把「账面值 vs 实际值」的**差额**，转出到现金账户 / 从现金账户转入。
2. **记账**：所有需要明细的支出/收入，全部**从现金账户走**。
3. **收尾平账**：记完明细后，按「本月现金 vs 上月现金」的差额，记一条**平账记录（一般性支出）**，确保现金账户总额归零。
4. 中间可人工**微调**（一般是修改既有记录）。

> 推论：现金账户是「中转枢纽」。所有差额、所有明细都汇聚到现金，最后用一条平账记录把它清零。

## 3. 目标 / 非目标 / 反目标

**目标**
- 三类账户：余额账户、负债账户、特殊账户（应收/应付，含逐条明细）。
- 主页可勾选展示哪些账户，汇总出「总资产」「净资产」。
- 平账 API、记账 API（收入/支出/转账）、周期账、单条修改。
- 账单流水页、资产页、负债页、应收/应付页、周期账管理页。
- Web 密码访问 + API 鉴权。
- 产出 skill 文档，供后续 AI 记账调用。
- 邮件备份。

**非目标**
- 不做社区、不做多币种、不做预算、不做投资分析。
- 不做原生 App，只做 Web（手机浏览器可访问即可）。
- 不做精细的日常流水（用户明确不在乎）。

**反目标（做出来就算失败）**
- 把现金账户逻辑做错（差额方向搞反、平账记录不归零）。
- API 无鉴权或鉴权形同虚设。
- 账户/分类模型与口袋记账不一致，导致用户迁移成本高。

## 4. 约束

- 后端 Node.js，前端 HTML（框架随意，倾向原生 JS + 少量 CSS，零构建）。
- 存储：SQLite 本地单文件（用户已确认）。
- 网页访问需密码；API 需鉴权（Bearer Token 或共享密钥）。
- 邮件备份：SMTP 配置项，填了才启用，未填则跳过。
- 周期账：应用内定时检查，到点自动生成记录。
- 界面风格对齐口袋记账截图：浅米白背景、蓝色主色调、多彩圆角账户卡片、数字键盘录入。

## 5. 方案（Approaches）

**方案 A：单进程 Node.js + SQLite + 原生 HTML/JS（选用）**
一个 Node 服务同时提供静态页面和 REST API，SQLite 存数据，前端原生 JS 渲染。
- 优点：零依赖构建、易部署、易备份（拷 .db 文件）、符合「本地工具」定位。
- 缺点：无热更新、前端手写 DOM 略繁琐。

**方案 B：Node.js + SQLite + Vue/React 前端**
- 优点：交互组件化更省心。
- 缺点：引入构建链，违背「框架随意、越简单越好」的暗示，部署重。

**方案 C：MySQL 8.0**
- 优点：用户熟悉 MySQL。
- 缺点：需额外装/配 MySQL，本地工具显得过重，用户已选 SQLite。

**结论**：选 A。理由——用户是「本地自用工具」，SQLite 单文件 + 单进程 Node 最简单可靠，备份即拷文件。

## 6. 已定的 How（用户拍板的部分）

- 存储：SQLite 本地文件（`data/zhangben.db`）。
- AI 记账形态：仅暴露鉴权 API + skill 文档，由外部 AI 调用（不内置 LLM 对话）。
- 周期账触发：应用内定时器（node-cron 风格）按规则到点生成。
- 邮件备份：SMTP 配置项（host/port/user/pass/收件人/频率），填了启用。

## 7. 留给 builder 的决策

- 具体依赖：`express` vs 原生 `http`、`better-sqlite3` vs `node:sqlite`、鉴权用 `jsonwebtoken` vs 简单共享密钥。
- 前端 UI 细节：颜色值、圆角、字体、卡片配色轮换方案。
- 分类体系：默认内置一版（从截图提取：餐饮/衣服鞋包/生活用品/话费/… + 收入类 工资/生活费/红包/… + 平账），可编辑。
- 账户卡片配色：从截图的多彩方案里抽一组循环色。

## 8. 数据模型（草案，供 builder 细化）

- `accounts`：id, name, type(asset/liability/receivable/payable), sub_label, balance, sort, shown, color, meta(json)
- `entries`（流水）：id, date, type(income/expense/transfer), category, account_id(从哪出), amount, note, is_balance(是否平账记录), created_at
- `receivable_payable_items`：id, account_id, name(借给谁/向谁借), amount, date, status(open/done), note
- `periodic_entries`：id, name, category, amount, account_id, cron/rule, next_run, enabled
- `categories`：id, type(income/expense), name, icon, color, sort
- `settings`：key, value（网页密码、API token、SMTP 配置等）

## 9. API 草案（供 AI 调用 + skill 文档引用）

- `POST /api/login` → 网页会话 token
- `GET/POST /api/accounts`、`POST /api/accounts/:id`（对齐余额/平账）
- `POST /api/accounts/flatten`（批量平账：给定各账户实际值，差额归入现金）
- `GET/POST /api/entries`（记账）、`PATCH /api/entries/:id`（微调）、`DELETE /api/entries/:id`
- `POST /api/entries/balance`（记一条平账记录，清零现金）
- `GET/POST /api/periodic`（周期账管理）
- `GET/POST /api/receivables`、`/api/payables`（应收/应付明细）
- `GET /api/report`（总资产/净资产/本月汇总）
- 鉴权：所有 `/api/*`（除 login）需 `Authorization: Bearer <token>`。

## 10. 页面清单

1. **资产页**：总资产/净资产卡片 + 账户列表（可勾选展示）+ 添加账户。
2. **负债页**：负债总额 + 负债账户列表（含还款日、剩余额度）。
3. **应收/应付页**：总额 + 逐条明细（借给谁/向谁借、金额、状态）。
4. **账单流水页**：按日期分组流水，可点开单条修改/删除。
5. **录入页**：收入/支出/转账三标签，分类图标网格 + 数字键盘。
6. **周期账管理页**：列表 + 增删改。
7. **设置页**：网页密码、API token、SMTP、备份。

## 11. 交付物

1. 可运行的 Node.js 应用（前端 + 后端 + SQLite）。
2. `SKILL.md`（记账 skill 文档，供后续 AI 调用 API 记账）。
3. 简短 README（启动、默认密码、如何配 SMTP、如何备份）。
4. 内置一套默认分类 + 示例账户。
