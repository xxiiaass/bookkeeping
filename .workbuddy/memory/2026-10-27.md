## AI 记账工具（从零搭建）

按用户提供的《账本开发.docx》需求 + 口袋记账 8 张截图，设计并实现了「为 AI 记账而生」的本地记账工具。

### 核心设计（灵魂）
用户一个月记一次总账，现金账户是「中转枢纽」：
1. 平账：各账户对齐实际余额，差额净流入现金
2. 记账：所有明细支出/收入全从现金走
3. 清零：按现金余额记一条平账记录，现金归零（差额=无法逐笔统计的一般性支出）

### 关键坑（已踩已修）
- better-sqlite3 里 SQL 字符串比较用 `<> ''`，不能写 `!= ""`（会被当成列名报 `no such column: ""`）
- ESM 下无 `__filename`，用 `import.meta.url` 派生 `__dirname`
- `node --test` 目录参数需通配符 `"test/**/*.test.js"`
- 登录返回 token 需直接带在响应里，避免前端二次请求 `/api-token` 的死锁（该接口要 Bearer token）

## 重要教训（务必记住）

### 1. 绝不要 `rm data/zhangben.db` 清数据
- 服务运行时 SQLite 是 WAL 模式，数据在 `zhangben.db-wal` 里。
- 直接 `rm` 主文件会导致数据不一致，且可能误删用户真实数据。
- 正确清理方式：停服务 → 用 SQL `DELETE FROM 表名` 删具体行，或用 `db.pragma('wal_checkpoint(TRUNCATE)')` 合并后再处理。

### 2. 备份必须先 checkpoint
- 备份 `.db` 文件前，必须 `db.pragma('wal_checkpoint(TRUNCATE)')` 把 WAL 数据合并回主文件。
- 否则备份出来的是空壳（无表无数据，只有 4KB）。
- 已修复：`src/backup.js` 的 `makeSnapshot` 里先 checkpoint 再 `fs.copyFileSync`。

### 3. 前端页面结构（照抄口袋记账）
- 资产页：资产(asset) + 应收(receivable)；负债页：负债(liability) + 应付(payable)
- 应收应付是"子类型"，明细在 receivable_payable_items 表，账户余额 = 未结清明细之和（syncReceivablePayableBalances）
- report 口径：总资产 = 资产 + 应收，总负债 = 负债 + 应付，只统计 shown=1 的账户
